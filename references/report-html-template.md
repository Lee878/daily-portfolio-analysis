# 报告 HTML 视觉与布局规范

> 从 SKILL.md 外迁。只在 Step 5 写 HTML 报告时读本文件，不占用分析流程的注意力。
> HTML 必须是**单文件自包含**（CSS 内联、不加载外部字体/图片/脚本），手机优先。

## 1. 全局样式

- 深色背景 `#0d1117`；卡片背景 `#161b22`；边框 `#21262d`；正文文字 `#e6edf3`；次要文字 `#8b949e`
- 涨/利好/多方：绿 `#3fb950`；跌/利空/空方：红 `#f85149`；强调/链接：蓝 `#58a6ff`；警告：黄 `#d29922`
- 字体栈：`-apple-system, BlinkMacSystemFont, 'Segoe UI', 'PingFang SC', 'Microsoft YaHei', sans-serif`
- 响应式 grid，手机竖屏优先；正文不小于 14px；卡片圆角 10-12px；内边距 12-16px
- 不使用任何外部资源（无 CDN、无外链图、无 JS 框架）

## 2. 报告结构（自上而下）

1. **标题栏**：报告类型 + 日期 + 时段
2. **组合总览条**：一排 4-6 个迷你卡片（总净资产/总持仓市值/现金/整体仓位/近期盈亏），金额用约值，汇率换算标"估算"
3. **市场大环境条（Regime 条）**：横向长条卡片
   - Regime 配色：S0/S6 红、S1/S3/S4 绿、S2/S5 黄
   - 必须显示"数据覆盖率 X%"，**X 直接抄 gate_check 输出的机械值**，旁边小字标"机械计算"
   - 覆盖率 <70% 时整条变黄并显示"只给定性判断"；降级报告（--allow-degraded）整条变红 + "数据不足"横幅
4. **跨报告对账条**（有上一期报告时）：较上次变化/假设确认或失效
5. **板块雷达**：每个板块簇一张卡片
6. **市场热点板块**：4-6 张小卡片
7. **持仓大卡片**（每只独立，禁止合并；顺序按"下一个开盘的市场优先"）
8. **新闻卡片**：4-8 张
9. **次日作战池**（盘后，表格）
10. **观察名单**：2-3 张，显著标注"现在不买"
11. **我不确定的是 / 数据缺口**：把证据文件 gaps 中仍未闭合的项逐条列出
12. **信息来源折叠区**：`<details>` 包裹
13. **免责声明**：固定在末尾

## 3. 持仓大卡片（核心组件）

完整版（盘前/盘后，400-500 字）固定包含：

- 头部：名称代码、成本/数量/浮亏比例、现价+涨跌、操作建议标签（加/减/持有/观望，不同底色）
- **市场位置**：现价、近 1 周/1 月/3 月涨跌、52 周分位、是否 price in、ATR 空间点位（Pivot/R1/R2/S1/S2）
- **环比同比 + 预期差**：与上期对比、市场预期、超/低于预期的后果、利好透支审计
- **多空双栏**（响应式，见 §4）：多方 3 条、空方 3 条
  - 每条论点文字后挂证据 ID，如 `[dp-007]` `[nw-002]` `[ch-001]`
  - **builder 直接写裸 `[xx-000]` 即可**：`run_daily.py report` 在双门 PASS 后会自动把所有裸 ID 统一包成弱化小胶囊徽标（class `rb`，电脑端 hover/title 显示级别与来源），已渲染的 `span.b` 徽标不会被重复包裹。无需每个 builder 手写徽标 HTML。
  - 徽标统一**中性灰**，禁止用绿/蓝涨跌色（避免与"多方/涨=绿、空方/跌=红"语义混淆）；P1/P2 仅略提亮，**只有 P4 弱证据/传闻用黄色虚线**提示"不可单独成论"。
  - **没有证据 ID 的论点不许出现在卡片里**（报告门会机械拦截；span 外不允许残留裸方括号）
- 共识 + 核心分歧（含验证方法）
- **风控行**：风险收益比（上行%:下行%）、止损位、目标位、合理入场区间，各附一句依据
- 板块标签：生命周期阶段、SEI 分值、中军龙头关系
- **证伪条件**：黄色虚框，1-2 条可观察的具体条件
- 操作建议：方向/仓位调整/持有周期/置信度

精简版（午间，150-200 字）：上午表现、异动归因（β/α）、多空核心分歧一句话、午后操作 + 价位 + 仓位；
保留证据徽标（至少 2 个唯一 ID），不做多空双栏。

## 4. 多空双栏响应式

```css
.bb { display: grid; grid-template-columns: 1fr 1fr; gap: 10px; }
@media (max-width: 768px) { .bb { grid-template-columns: 1fr; } }
```

- 手机竖屏（<768px）：多方绿块在上、空方红块在下，纵向堆叠
- 电脑横屏（≥768px）：左右并排
- 多方块底色用低饱和深绿（如 `rgba(63,185,80,.08)`）+ 绿色左边框；空方块同理用红

## 5. 板块卡片

- 左边框颜色：利好绿 / 利空红 / 分化黄
- 内容：板块名 + 所含持仓、状态标签、2-4 条消息（区分短期情绪与长期趋势）、一句结论（拿住/减/等）
- 底部小字三元组：`生命周期：强化期` · `SEI：55（良性分歧）` · `中军龙头：健康共振`

## 6. 新闻卡片四要素

分类标签（宏观/美股/A股/港股，不同颜色）+ 一句话标题 + 2-3 句摘要 + 对持仓影响（利好/利空/中性 + 影响谁、为什么）。
卡片上标注来源与证据级别徽标；P4 传闻必须黄字标"未经证实"。

## 7. 重大事件警告框

FOMC/CPI/非农/重磅财报当周：黄色警告框突出，内含 A/B/C 三情景（触发数据门槛/执行战法/禁忌/概率）。
非事件周不显示该框。

## 8. 信息来源折叠区

```html
<details style="...">
<summary>信息来源与取证记录（点击展开）</summary>
  <ul>
    <li>搜索关键词：……</li>
    <li>行情/财务：seed_finance_lookup、akshare（数据点 ID 区间 dp-001~dp-0xx）</li>
    <li>新闻与公告：逐条列名称 + URL（对应 nw-xxx）</li>
    <li>产业链来源：（对应 ch-xxx）</li>
  </ul>
</details>
```

## 9. 免责声明（固定文案要点）

仅为研究分析与决策参考，不构成投资建议或买卖指令；不承诺收益、不保证准确性；
信息来自公开渠道，可能存在时效性不足；投资决策与后果由用户自行承担。

## 10. 交付前 HTML 自查

- 在浏览器中以手机宽度（约 390px）打开检查：无横向溢出、多空双栏已变上下、文字不重叠
- 每个证据徽标的 ID 都能在 evidence JSON 中找到
- 覆盖率数字与 gate_check 输出逐字一致
- 单文件双击可打开，无外部依赖请求
