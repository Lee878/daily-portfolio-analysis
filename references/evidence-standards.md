# Evidence Standards

证据分级标准和来源管理规范。

## 证据强度四级分级（P1-P4）

> 整合自 stock-prompt v8.0.0 公共研究契约体系。
> 原有的强/中/弱三级体系升级为四级 P1-P4，更精细，更可操作。

### P1 级：最高权威（可直接采信）

官方原始来源，不需要额外验证：

- 交易所官方公告（年报、季报、临时公告、招股书）
- 监管机构文件（证监会、SEC、交易所问询函、处罚决定）
- 原始财务数据（财报原文、现金流量表、资产负债表）
- 官方统计数据（统计局、央行、行业协会数据）
- 公司官方投资者关系活动记录（财报电话会、投资者日）
- 官方合同/订单/中标公告
- 专利、标准、技术论文

### P2 级：高可信（需要交叉验证）

主流权威媒体和专业机构，可信度高但仍需注意立场：

- 主流财经媒体报道（彭博、路透、财新、华尔街日报、新华财经）
- 券商研究报告（注意：券商有利益关联，需要打7折）
- 行业协会报告
- 专家访谈/管理层访谈（非管理层本人）
- 行业会议公开信息
- 上下游上市公司交叉验证

### P3 级：中等可信（数据准确，解读有偏差）

行情软件和数据服务商，数据本身准确，但分析解读可能有偏差：

- 东方财富/同花顺/腾讯证券等行情软件数据
- Wind/ Choice 等金融终端数据
- 龙虎榜、资金流向、融资融券数据
- 北向/南向资金流向数据
- 技术指标计算结果

### P4 级：低可信（只能作为线索）

网络公开内容，噪音多，只能作为线索不能作为决策依据：

- 社媒帖子（雪球、知乎、Twitter、Reddit、股吧）
- KOL/大V观点
- 小道消息、市场传闻
- 自媒体文章
- 个人博客观点
- 无明确来源的价格异动

## 证据使用规则

1. **每个核心结论至少有一条 P1/P2 级证据**
   - 如果只有 P3/P4 级证据，必须明确标注"此判断基于低级别证据，需要进一步验证"
   - P4 级证据不能单独作为决策依据

2. **传闻必须标注来源和级别**
   - 不能说"市场传闻"，要说"据 XX 平台某用户爆料，P4 级证据，未经证实"

3. **券商观点要打折**
   - 券商买入评级通常偏乐观，可信度打7折
   - 注意看分析师有没有持仓、有没有承销关系

4. **数据必须可追溯**
   - 每个数字都要能说出来源
   - 不确定的数据要标注"估算"或"待验证"

5. **反证优先**
   - 先找否定自己观点的证据
   - 如果找不到反证，说明可能有确认偏误

6. **独立证据族原则**
   - 同一底层来源的多个报道，只算一个独立证据族
   - 例如：10个财经号转载同一份公告，还是一个证据族，不是10个
   - 来源数量 ≠ 可信度

7. **论点必须挂证据 ID（报告门机械校验）**
   - 多空辩论与报告中的每条论点，末尾必须引用证据 ID（[dp-xxx]/[nw-xxx]/[ch-xxx]）
   - 完整版每只标的唯一 ID ≥4、引用总次数 ≥6；午间精简版唯一 ID ≥2
   - 引用的 ID 必须在证据文件中真实存在（禁止编造）
   - P4 ID 不得作为一条论点的唯一引用，违反超过 2 条，报告门 FAIL

## 证据登记（强制前置）

所有证据必须登记在 `evidence/<日期>_<时段>_<代码>.json`，字段与 ID 规范见
[evidence-schema.md](evidence-schema.md)。由 `scripts/fetch_data.py` 生成骨架，
agent 补证写回同一文件；**没有证据文件，证据门直接 FAIL，禁止进入辩论。**

- 数据点 ID：`dp-001…`；新闻：`nw-001…`；产业链笔记：`ch-001…`
- 报告论点引用 ID：`铜库存连续三周下降 [dp-007][nw-002]`
- 报告中的数字必须能按 ID 在证据文件中找到（holdings.md 的成本/数量除外）
- `missing` 点必须写入 `gaps`；脚本会逐点核对，漏报缺口直接阻断

## 数据覆盖率审计（机械计算，禁止口述）

覆盖率**唯一权威值是 `scripts/gate_check.py --stage evidence` 的输出**，
报告横幅照抄该值（偏差 >3 个百分点，报告门 FAIL）。计算口径如下，agent 不得自创算法。

### 点状态计分

| status | 计分 | 说明 |
|---|---|---|
| verified | 1.0 | 有来源、有时间、级别明确 |
| estimated | 0.5 | 估算/外推值，必须注明口径 |
| missing | 0 | 未取到，且必须进 gaps |

任何 `P4` 级数据点即使标 verified，覆盖率中最高只按 0.5 计。

### 维度权重

| 维度 | 股票权重 | 基金权重 |
|---|---:|---:|
| 基本面 fundamental | 25% | 40% |
| 技术面 technical（基金为净值面） | 20% | 30% |
| 资金面 flow | 20% | —（并入其他维度归一化） |
| 新闻 news | 20% | 15% |
| 产业链 chain | 15% | 15% |

- 数值维度得分 = 该维度计划点计分之和 / 计划点数（计划点清单见 evidence-schema.md §4）。
- 新闻维度得分 = min(有效新闻条数 / 最低条数要求, 1)。有效新闻 = 有可访问 URL 且级别 P1/P2/P3；
  完整版最低 2 条且至少 1 条 P1/P2，午间最低 1 条。
- 产业链得分 = min(有效 chain_notes 条数 / 最低要求, 1)，股票每时段至少 1 条。
- 组合覆盖率 = 各持仓覆盖率的等权平均（holdings 提供市值后可升级为市值加权）。

### 覆盖率等级与操作限制（门禁强制执行）

| 覆盖率 | gate 行为 | 允许的结论强度 |
|:---:|:---|:---|
| ≥70% | PASS | 可给具体操作建议、仓位、价位 |
| 50%-69% | PASS 但警告 | 只给定性判断，禁止精确评分/具体仓位数字 |
| <50% | 默认 FAIL；`--allow-degraded` 后为 DEGRADED | 只列已知事实与待补清单，报告顶部挂"数据不足"横幅 |

无论覆盖率多高，**硬必需项（股票最新价+当日涨跌幅、基金最新净值）未 verified 一律 FAIL**；
新闻/产业链最低条数不达标一律 FAIL。

### 缺失数据处理规则
- 核心模块缺失也要保留数据点并标 missing + gaps，说明缺失对结论的影响
- 不同来源、日期或统计口径的数据不得直接拼接计算
- 来源冲突时并列披露并降低置信度，不得擅自选一个

## 红旗信号

出现以下情况时，降低置信度：

- 投资逻辑主要依赖单一客户传闻
- 股价上涨主要因为社媒关注，没有基本面支撑
- 公司在机会转化为收入前需要融资
- 客户未具名，收入影响模糊
- 存货和应收账款增速快于收入增速
- 声称稀缺但毛利率并未改善
- 管理层用主题概念说话，但分部数据没有变化

## 证据链模板

每个核心判断都应该有完整的证据链：

```
判断：[我认为X会上涨/下跌]
依据：
1. [强证据1] —— 来源：[具体出处]
2. [中证据2] —— 来源：[具体出处]
反证：
- [可能否定这个判断的因素]
- [如果出现什么情况，说明我错了]
证据强度：强/中/弱
置信度：高/中/低
```
