## 一、先说诊断：问题不在配色，在信息架构

原版（v2.4.0 深色）视觉上已经"干净"，但实际阅读负担很重。逐条实测：

| 现象 | 实测数据 | 后果 |
|---|---|---|
| 证据徽标内联在正文 | **147 个 / 1.7 万字**，平均每 117 字一个灰底方块 | 眼睛不断被小方块打断，读不下去 |
| 首屏前置层数 | 顶栏 → h1 → 长副标 → 覆盖率+200字机器说明 → 6格指数 → Regime → 目录 = **7 层** | 手机滑 2 屏才看到第一张卡 |
| 关键数字被降级 | 成本/现价/股数全挤在 `.sub` 13px 灰字里，**浮盈根本没算** | 最该看的仓位信息藏在最不起眼的地方 |
| 大势占满首屏 | Regime 单段 400+ 字，直接铺开占掉 60% 屏幕 | 首屏没有任何数字和动作 |
| 无区块导航 | 整页 **19,963 px**，约 24 屏 | 找一只标的只能硬滑 |
| 容器形态混用 | 25 张卡片 + 14 个 h2 + 表格在手机变卡片 | 三种视觉语言互相打架 |
| 证据溯源指向错误 | 每个标的的 ID 都从 `dp-001` 重新编号，`load_id_meta` 用全局 dict 装 → 后写覆盖先写 | 点"来源"跳到**别的标的**的链接；门禁查不出来（每文件内部自洽） |

## 二、六项改进（两版共享）

1. **证据徽标从正文剥离** → 收进卡片底部「证据 13 条 · 2 条待补」折叠，清单照旧保留。
   溯源能力不丢，正文干净了。

2. **成本 / 现价 / 浮动 三格数据条**
   从 `code` 字段解析出「28股 成本357.577 现价340.16」，**自动算出浮盈 −4.87%**。
   这是原版完全缺失的信息——有成本却不算盈亏，是这类报告最大的可读性损失。

3. **证据按标的分桶**
   `load_id_meta` 全局 dict → `{标的: {id: meta}}`。
   实测证据条目 **22 → 324 条**，且每张卡的"来源"指向自己那份证据。

4. **大势折叠**
   Regime 默认 3 行 + 渐隐遮罩 + 「读全文 ↓」，纯 CSS `<details>`，无 JS。

5. **区块目录**
   横向 chip 直接跳区块。标题里的括号补充说明剥离，只留主标题（「跨报告对账（核销…）」→「跨报告对账」）。

6. **段落列表化**
   prose / alert 里的并列要点加小圆点标记，不再是一堵连续文字。

另外：**覆盖率机器口径说明从首屏移到页面底部「数据来源与口径」**——它是资料，不是今天要读的东西。

## 三、两版视觉语言

信息架构完全一致，**只换视觉语言**，所以选择纯粹是审美判断。

| | **A · Terminal（深色）** | **B · Brief（浅色）** |
|---|---|---|
| 气质 | 交易终端 / 盯盘面板 | 报纸晨报 / 读物 |
| 底色 | `#0a0d12` 近黑 | `#faf9f6` 暖白 |
| 卡片 | 深色卡片 + 3px 动作状态条 | 无盒子，发丝线 + 大留白切分 |
| 标题 | 无衬线 17.5px，字重 660 | 衬线 21px，字重 600 |
| 分隔 | `rgba` 发丝线 | 1px 实线 + 点线 |
| 指数区 | 深底格子，1px gap 做线 | 横排大数字 + 竖线分栏 |
| 强调色 | 蓝 `#4d9fff` / 金 `#f0b429` | 靛蓝 `#1c4b78` / 古金 `#8f6119` |
| 适合 | 夜间、暗光、信息密度优先 | 白天、长文、连续阅读 |

**共同约束**：红涨绿跌（A股习惯）、数字全部 `tabular-nums`、正文级文字对比度全部 ≥ 4.5:1（WCAG AA，`a11y_check.py` 实算 33 组）。

## 四、推荐：B（浅色）

理由：

1. **内容本质是"读物"不是"面板"。** 报告 1.7 万字里大部分是解读性文本（大势、共识、证伪），指标只有 6 个指数。用面板语言装长文是错配。
2. **浅底长文疲劳更低。** 深色底上看大段中文，白字发光感强；这是手机日报最常见的抱怨来源。
3. **浅底红绿更接近A股直觉。** 深色底上红绿对比强烈但发飘，浅底更像财经终端。
4. **"日报"这个词本来就该是报纸。**

A 版的适用场景：你想让报告看起来像盯盘软件，或者你主要在暗光下看。
