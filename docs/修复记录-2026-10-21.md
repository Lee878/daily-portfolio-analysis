## 一、会影响报告质量 / 呈现的改动（重点看这 5 条）

这 5 条不是"修 bug"，是**改变了报告长什么样、门槛有多严**，你需要知道：

| # | 改动 | 对报告的实际影响 |
|---|---|---|
| 1 | **覆盖率分母不再读 evidence 里的 `planned`** | 覆盖率数字会**普遍下降**（更真实）。以前删掉 `planned` 能刷到 100%，现在按 market/session 机械算。可能有个股从 PASS 掉到 WARN（50-69%），甚至 <50% 被拦。这是把"机械覆盖率"还原成真的机械值 |
| 2 | **`status=verified` 的数值字段必须是数字** | `main_net_inflow` 这类字段不能再填"10/19获融资买入2.44亿…"这种话，必须填数值（亿元/万元），文字放 `note` 或降级 `estimated`。**门槛变严**，证据门会多拦一类情况 |
| 3 | **报告切片改为按卡片边界** | 报告门判得更准：以前能靠相邻卡片"蹭引用"过关的薄卡片，现在会真的 FAIL；反过来，"空方 0 个 ID"的误杀也消失了。等于**门禁两端都收紧到正确位置** |
| 4 | **市值统一"亿元"、资金流统一"万元"** | 报告里出现的是"7777 亿"而不是一长串元；akshare 拉到的数不会再被当成伪造。数字口径变统一，**历史报告里混用的元/亿不再出现** |
| 5 | **4 只场外基金重新进入取证与报告** | 华安黄金、华泰柏瑞红利、易方达半导体、华夏恒生科技以前被静默漏掉（报告里没有它们的卡片），现在会正常出卡。**报告篇幅会变长，覆盖率分母也多了 4 只** |

另有一条视觉但**未改动**：引擎用的是美式配色（涨=绿、跌=红），与你 A 股习惯（涨红跌绿）相反。改它会让所有历史报告的配色语义翻转，容易看反，所以我没动——你说一声我就改（`.g`/`.r` 两个色值）。

## 四、你接下来怎么用

```bash
# 1) 解包到部署目录（示例）
tar -xzf portfolio-migrate-2026-10-21-v2.3.0.tar.gz -C <你的部署根目录>

# 2) 体检（单副本部署不需要 DAILY_RT）
python engine/scripts/release.py doctor          # 期望：全部健康 [OK]

# 3) 当天第一次取证（网络可用时去掉 --no-network）
python engine/scripts/fetch_data.py --holdings holdings.md --session pre --date 2026-10-22
python engine/scripts/run_daily.py gate --session pre --date 2026-10-22 --holdings holdings.md

# 4) 补证 + 填 data.json 后出报告
python engine/scripts/run_daily.py report --session pre --date 2026-10-22 \
    --holdings holdings.md --data <绝对路径>/data.json
```

> 三份 `WorkBuddy prompt-*.md` 已同步更新：doctor 只校验 ENG 指纹 + 测试；并补了"gate 返回 11 时怎么处理"。
