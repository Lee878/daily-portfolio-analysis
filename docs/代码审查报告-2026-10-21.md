## 一、架构与核心逻辑（读过之后的判断）

五层结构，真正有强制力的是第 2 层：

```
cron 模板(极薄,只触发) → run_daily.py 编排 → fetch_data.py 生成证据骨架
                              ↓
                     gate_check.py 证据门(价格/新闻/产业链/覆盖率/防伪)
                              ↓
               agent 补证 + 四层分析 + 填 data.json(不写 HTML)
                              ↓
        render_report.py 套 assets/style.css 出 HTML → 报告门(引用/覆盖率/多空不同源)
                              ↓
        双门 PASS 才写入 <meta name="daily-gate"> 签名 → 才允许交付
```

**设计上真正成立的三件事**（这是这套系统的价值，迁移时不能丢）：

1. **退出码硬阻断**：证据门不过 builder 根本不跑（10/11）；报告门不过 HTML 物理删除（12）。不依赖模型自觉。
2. **指纹体系**：VERSION + MANIFEST + `release.py verify/doctor`，防"逐日放水"和传输损坏。
3. **数据驱动渲染**：agent 只填 data.json，CSS/免责/卡片壳固化。这一层实际执行得不错——我用真实证据 + 手写 data.json 跑通了端到端（双门 PASS、签名写入），说明主链路是活的。

**设计上不成立的地方**：所有"机械校验"的输入（`planned`、`status`、`value`）都在 agent 可改的同一个 JSON 里。详见 P1-08/09——这不是代码 bug，是威胁模型的漏洞。

## 三、问题清单（按严重程度）

### P0 · 阻断级：迁移后一条报告都出不来

#### P0-01 Windows 文件名崩溃：`safe_name` 不处理反斜杠
- **位置**：`engine/scripts/fetch_data.py:788`、`gate_check.py:218`（两处同构）
- **触发**：`holdings.md` 基金段有一行 `帮你投 \| 全球精选100（ADVISORY）`，Markdown 转义竖线后 `cells[0]` 变成 `帮你投 \`。`safe_name()` 只替换 `. / :`，反斜杠原样进文件名。
- **后果**：Linux 上 `\` 是合法文件名字符（豆包环境所以一直没炸）；Windows 上是路径分隔符 →
  ```
  FileNotFoundError: ...\evidence\2026-10-21_pre_帮你投 \-全球精选100（ADVISORY）.json
  ```
  fetch_data 直接 traceback 退出，run_daily 判环境错误（2），**每天 8:30/20:00 都死在第一步**。
- **修复**（向后兼容，只增不删，历史证据文件名不变）：
```python
def safe_name(ticker):
    out = str(ticker)
    for ch in (".", "/", ":", chr(92), "*", "?", '"', "<", ">", "|"):
        out = out.replace(ch, "_")
    return out
```
- **验收**：`fetch --no-network` 在含该持仓的 holdings.md 上跑完不报错。

#### P0-02 场外基金全部漏取证 → 证据门必然 FAIL
- **位置**：`fetch_data.py:200`（`if len(cells) < 4: continue`）vs `gate_check.py:116`（`if len(cells) < 2`）
- **触发**：真实 `holdings.md` 基金表只有 3 列（`基金名称 | 金额 | 持有收益`）。fetch_data 要求 ≥4 列 → 4 只场外基金（华安黄金、华泰柏瑞红利、易方达半导体、华夏恒生科技）**一条证据都不生成**；gate_check 用 ≥2 列，能解析出来。
- **后果**（实测，空 daily-reports）：
  ```
  ✗ [华安黄金ETF联接C（000217）] 缺少证据文件 ...
  ✗ [华泰柏瑞中证红利低波动ETF联接C（007467）] ...
  ✗ [易方达半导体材料设备ETF联接A（021893）] ...
  ✗ [华夏恒生科技ETF联接(QDII)C（013403，定投）] ...
  → 退出码 10，管道卡死
  ```
  豆包上没暴露，是因为 1280 份历史报告里的基金证据是历史遗留/一次性 `fill_*.py` 补的，不是 fetch 产出的。**换台新机器必然复发**。
- **修复**：把 fetch_data 的基金分支放宽到 `len(cells) >= 2`，并对 3 列表 `amount=_to_float(cells[1])` 保持现状：
```python
if len(cells) < 2:      # 原为 < 4
    continue
```
  同时**消除双解析器分歧**（见 P2-12）：建议两边都只认 `^## 名称持仓` 形式，并加一条一致性单测——同一份 holdings.md，两个 parse 结果必须相等。
- **验收**：全新目录 `fetch --no-network` 后标的数 = `gate` 报告的标的数（当前 13 vs 17）。

### P1 · 严重：能跑但结果不可信 / 平台不兼容

#### P1-03 中文 Windows 控制台编码崩溃（连"问题清单"都打不出来）
- **位置**：`gate_check.py:912`（`print(f"  ✗ {p}")`）、`run_daily.py:406`（`✅`）
- **触发**：Windows 任务计划/cmd 重定向输出时默认 GBK（cp936）；`✗`(U+2717)、`✅`(U+2705) 不在 GBK 内。
- **后果**（实测 `PYTHONIOENCODING=gbk`）：
  - 失败路径：`UnicodeEncodeError`，**problems 列表完全打不出来**（这套系统的反馈闭环就断在这），退出码变 1 而不是 10；
  - 成功路径：HTML 已生成、签名已写入，但进程退出码 1 → 上层判失败，好报告被当坏报告。
- **修复**（双保险）：
```python
# 三个入口脚本 main() 最前面
try:
    sys.stdout.reconfigure(encoding="utf-8", errors="replace")
    sys.stderr.reconfigure(encoding="utf-8", errors="replace")
except Exception:
    pass
```
  同时把 `✗`/`✅`/`!` 换成 ASCII（`[X]`/`[OK]`/`[!]`），并在 Windows 运行脚本里 `set PYTHONIOENCODING=utf-8`。

#### P1-05 单位口径冲突：akshare 给"元"，门禁按"亿元"卡
- **位置**：`fetch_data.py:446`（`market_cap` 直接取"总市值"，单位元）、`fetch_data.py:456-459`（`main_net_inflow` 单位元）；`gate_check.py:313` `market_cap` 区间 `(30, 1e10)`（实为"亿元"）、`:293` `main_net_inflow` `(-1e7, 1e7)`（实为"千万元"）
- **实测**：紫金矿业真实市值 7.78e11 元、主力净流入 2.4e8 元 →
  ```
  数据点 dp-003（market_cap）=777840000000.0 超出合理区间 (30, 10000000000.0)
  数据点 dp-004（main_net_inflow）=240000000.0 超出合理区间 [-10000000.0,10000000.0]
  ```
- **后果**：豆包上 akshare 403 从没拉到过值，所以问题潜伏；**WorkBuddy 网络一通，A股/港股每只持仓都会因"疑似伪造"被证据门拦死**。而人工补证写的是"亿元"（历史证据里 601899=7776.84），两套口径并存。
- **修复**（统一到"亿元/万元"，写进 evidence-schema）：
```python

if k == "market_cap" and v is not None:
    v = round(v / 1e8, 2)          # 元 → 亿元

```

#### P1-06 报告门切片错配卡片 → 既可误杀也可漏放
- **位置**：`gate_check.py:640-655` `_slice_sections` / `:627` `_name_pattern`
- **触发**：按"名称/代码出现位置"切章节，但匹配不排除 HTML 属性。`2026-10-20` 真实报告里紫金卡片的徽标 `title="P1 · 中芯国际官方"` 含"中芯国际" → 从该属性处切断，后半段（含紫金"空方"整行）被算给中芯国际。
- **实测**：`中芯国际` 切片长度 10340 字符，含紫金"全维持成本"与通富内容；结果 14 张卡片全部报"空方 0 个ID"、中芯国际报 `[nw-002] 重复 17 次`，报告门 26 条阻断。
- **性质**：CHANGELOG 2026-10-20 修过同类问题（KO→KOSPI），只加了词边界，**没解决"在标签属性里匹配"这个根**。方向相反时同样成立：相邻卡片的引用会灌进薄卡片，让它**假 PASS**。
- **修复**：优先按卡片边界切，再在"去标签纯文本"里认票：
```python
def _slice_sections(text, holdings):
    blocks = re.findall(r'<div class="card[^"]*">[\s\S]*?</div>', text)
    if blocks:
        out = {}
        for b in blocks:
            plain = re.sub(r"<[^>]+>", " ", b)   # 关键：先剥标签属性
            for h in holdings:
                names = {h["name"], h["ticker"], h["ticker"].split(".")[0]}
                if any(nm and _name_pattern(nm).search(plain) for nm in names):
                    out[h["ticker"]] = out.get(h["ticker"], "") + b
                    break
        if out:
            return out
    ...  # 兜底沿用原位置切片，但先把 title="…"/alt="…" 内容清掉
```
- **验收**：拿 2026-10-20 真实 HTML 重跑报告门，"空方 0 个ID"类问题应消失或只剩真实问题；单测补一条"属性含其它票名"的用例。

#### P1-08 覆盖率分母可被改：删掉 `planned` 就是 100%
- **位置**：`gate_check.py:225-246`（分母取 `ev["planned"]`）、`:443-460`（`used_w` 只累计"有计划"的维度）

#### P1-09 `verified` 只认状态字段，字符串占位照样满分
