## 三、与 NeoData 的互补关系（核心价值）

现有 NeoData 有三个已知取不到的字段，这两个 skill 正好各补一块：

| NeoData 缺口 | 补位通道 | 实测 |
|---|---|---|
| `north_south_flow`（北向资金） | a-stock-data `hsgt_realtime()` | ✅ 261 行分时 |
| `put_call_or_inst`（美股期权/机构） | global-stock-data `options_chain_cboe()` | ✅ NVDA 完整链 |
| `fund_scale_change` / `manager_change` / `top_holdings` | a-stock-data 有 F10 九大类、ETF 份额；**场外基金未验证** | ⚠️ 部分 |
| `fund_flow`（日级资金流序列） | 依赖 push2his → **不可用** | ❌ 仅有快照 |

结论：**新增两个源后，字段覆盖可以从"5 个缺 3 个"提升到"5 个缺 1 个"**（场外基金仍缺）。

## 四、字段口径对照（对报告的直接价值）

### 4.1 A股 `tencent_quote()` 返回字段

`name, price, last_close, open, change_amt, change_pct, high, low, amount_wan,
turnover_pct, pe_ttm, amplitude_pct, float_mcap_yi, mcap_yi, pb, limit_up, limit_down,
vol_ratio, pe_static, is_stale`

**三个直接可用的发现**：

1. **`vol_ratio` 量比是现成的** —— 不必再自己算 `volume_ratio`。
2. **单位已经是「亿元 / 万元」** —— `mcap_yi`、`amount_wan` 与报告口径天然一致，无需换算。
3. **`is_stale` 字段** —— 数据源自己标注是否为陈旧快照，可用于门禁判断「是否真实现价」。

### 4.2 52 周区间不必自己统计

- 港股：`high_52w` / `low_52w`
- 美股：`high_52w` / `low_52w`

`range_52w_pct` 可直接由这两个值算出，不必再遍历一年日线。
（`atr14` 仍需从 K 线派生，`derive_indicators.py` 已实现，继续用它。）

## 五、集成建议

### 5.1 不要运行时读 SKILL.md

两个文件合计 62 万字节、133 个代码块。每次让 agent 读进来再复制执行，代价是：
- 上下文开销巨大（单次可能吃掉数万 token）；
- 抽取时容易把文档里的树状图、示例片段误当代码（本次实测就踩到，91 块中 24 块无法直接执行）；
- 无法进 CI 回归。

### 5.2 抽成适配器落库（推荐）

按 PRD `docs/PRD-日报产品化-v1.0.md` 的 FR-13 / FR-14：

```
scripts/adapters/
├── __init__.py
├── a_stock_tencent.py    # tencent_quote / tencent_kline
├── a_stock_baostock.py   # 日线兜底（纯 socket，最稳）
├── a_stock_north.py      # hsgt_realtime 北向资金
├── global_sina.py        # 美股实时 / 日线（注意取 tail）
└── global_cboe.py        # 期权链 → put/call ratio
```

每个适配器实现统一接口：

```python
def fetch(field: str, ctx: dict) -> tuple[value, source_note] | None
```

### 5.3 建议的字段优先级链

```json
{
  "close":        ["tencent", "baostock", "neodata"],
  "kline_daily":  ["baostock", "tencent"],
  "volume_ratio": ["tencent"],
  "pe_ttm":       ["tencent", "neodata"],
  "mcap":         ["tencent", "neodata"],
  "north_flow":   ["hsgt", "neodata"],
  "put_call":     ["cboe"],
  "news":         ["neodata", "eastmoney"],
  "fund_nav":     ["neodata"]
}
```

理由：腾讯不封 IP、字段最全，放实时行情首位；baostock 纯 socket 最稳，放日线首位；
东财系只用于独有数据，不进关键路径。

## 六、坑与注意事项

| # | 坑 | 说明 |
|---|---|---|
| 1 | `push2his` 不可用 | 东财历史行情与日级资金流序列拿不到，只有快照 |
| 2 | `us_stock_kline_sina` 的 `num` 不生效 | 传 5 仍返回全历史，必须自己取 `tail(n)` |
| 3 | mootdx 未通过 | 通达信 TCP 通道在本机没取到数据，别把它当主源 |
| 4 | 百度 K线风控 | 触发 `hit risk`，不要重试，直接换源 |
| 5 | 腾讯/新浪返回 GBK | 解码要显式处理，否则中文乱码（本次 curl 直接看就是乱码） |
| 6 | 东财限流 | skill 内部已有 `em_get()` 串行限流，抽适配器时要保留 |
| 7 | 许可证 | Apache-2.0，抽取代码须保留版权声明与来源链接 |
| 8 | httpx 版本 | 装 mootdx 带入 httpx 0.25.2；若平台组件要求 0.27+，注意隔离环境的版本冲突 |

## 七、结论

1. **两个 skill 都可以作为数据源**，且不是"锦上添花"，是补现有缺口的关键两块。
2. **真正可用的通道集中在腾讯、新浪、CBOE、baostock 与官方机构端点**；东财系只作补充。
3. **落地方式选"抽适配器"，不选"运行时读 SKILL.md"**：上下文成本、稳定性、可回归三条都支持这个结论。
4. 抽完适配器后，`references/mcp-data-source.md` 的缺口表可以更新：北向资金与美股期权从「缺」改为「有」。
